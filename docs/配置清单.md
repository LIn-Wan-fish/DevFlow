## 一个已知的偶发问题(不影响功能)

Agent Eval 里的 `no-evidence-question` 用例**偶尔**失败(10 次里约 1~2 次):

- **答案本身是对的** —— 明确说「当前仓库里没有『量子纠缠』模块」
- 但模型换了个泛化说法去检索(如「模块 设计」),某条**弱命中**通过了离题门限,
  被挂成了引用,而答案同时说"这不构成证据"
- 断言 `citations_present: false` 因此不成立

这是**检索门限的调优问题**,不是功能缺失。已经修过一轮(绝对词项条数门限),
但模型可以换别的措辞绕过去。要彻底解决需要在引用挂载那一层再做一次相关性判定。

## 附录:本机环境的三个坑

**1. Docker Desktop 必须从开始菜单启动。** 由脚本/终端拉起的话,会话结束时可能被连带终止。

**2. GitHub 加速器(Steam++ / Watt Toolkit)会让容器连不上 GitHub。**
`pwsh -File scripts/enable-github-accelerator.ps1`,只有 `DATA_SOURCE=github` 时需要。

**3. 构建镜像时直连 PyPI 可能超时。** ragas 容器支持 `--build-arg PIP_INDEX_URL=<镜像源>`,
本机用阿里云源构建成功;默认仍是官方源,没有写死任何镜像。
