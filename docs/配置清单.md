## 现在就能演示什么

`DATA_SOURCE=github` + 你的真实仓库,打开 http://localhost:3000 可以直接演示:

| 演示 | 说法 |
|---|---|
| **多 Agent 冲突检测** | 「检查当前 Issue、PR 和失败 CI,判断这个版本是否可以发布」→ Observer 会报出「PR 说可合入、CI 说失败」「PR 自己的结论与 findings 矛盾」等 5 条冲突 |
| **CI 排障** | 「CI 为什么失败」→ 会如实说**日志拉不到**(`startup_failure` 本就不产生日志),并解释这与 Issue 描述的失败现象是自洽的 |
| **写操作闸门** | 「给 Issue #1 写一条查询评论草稿」→ 出草稿不执行;切 viewer 确认会被 403 并留痕;切 member 确认**真的发到 GitHub** |
| **跨会话记忆** | 右栏批准候选 → 换会话再问,召回时标记「已确认记忆」 |
| **逐 token 流式** | 真实模型回答时字是逐个出现的,不再是长时间空白后整段蹦出 |

> 想回到离线快照演示:`.env` 改 `DATA_SOURCE=snapshot` → `docker compose down -v && docker compose up -d`。

## 附录:本机环境的两个坑

**1. Docker Desktop 必须从开始菜单启动。** 由脚本/终端拉起的话,会话结束时可能被连带终止
(现象:`docker info` 突然连不上,`wsl -l -v` 显示 `docker-desktop` 变 `Stopped`)。这个会话里被杀过三次。

**2. GitHub 加速器(Steam++ / Watt Toolkit)会让容器连不上 GitHub。**
一键方案:`pwsh -File scripts/enable-github-accelerator.ps1`
**只有 `DATA_SOURCE=github` 时才需要。** ⚠️ 这等于让容器信任一个本地中间人根证书,默认不开启。
