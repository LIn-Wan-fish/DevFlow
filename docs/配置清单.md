## 第 2 步(你选的):在网页配置仓库 Secret ⏱ 1 分钟

1. 打开 **https://github.com/LIn-Wan-fish/portfolio-demo/settings/secrets/actions**
   (或:仓库页 → **Settings** → 左侧 **Secrets and variables** → **Actions**)
2. 点绿色按钮 **New repository secret**
3. **Name** 填 `GITHUB_TOKEN`,**Secret** 粘贴你的 PAT
4. 点 **Add secret**

**但请先想清楚是否需要**:

- 这个项目的 CI(`.github/workflows/ci.yml`)跑的是**全离线测试** ——
  后端用 SQLite 内存库 + 进程内向量库,前端是纯组件测试,两边都不联网、不打真实模型。
  **所以它不需要任何 Secret。**
- 运行时需要 token 的是**本地 Docker 里的后端**,那读的是 `.env`,不是 Actions Secrets。
- 只有当你想**在 Actions 里跑真实 GitHub 集成**(比如定时同步)时,这个 Secret 才有用。

换句话说:第 2 步**可以跳过**。跳过不影响任何已实现的功能。

## 第 3 步(可选):给令牌补权限

细粒度 PAT 的权限**逐仓库**授予,而且**读了不代表能写**。实测矩阵:

| 想做的事 | 需要的权限 | 现在还差 |
|---|---|---|
| 读 Issue / PR / CI / 日志(同步数据) | 各 `Read` | ✅ 已有 |
| 创建 Issue | `Issues: Write` | ✅ 已有 |
| **修改 Issue、加标签** | `Issues: Write` | ❌ 同一令牌下 403 |
| 提交文件到分支 | `Contents: Write` | ✅ 已有 |
| **开 PR** | `Pull requests: Write` | ❌ |
| 提交 `.github/workflows/` | `Workflows: Write` | ❌ |
| 写仓库 Secret | `Secrets: Write` | ❌ |

**怎么补**:GitHub → 右上头像 → **Settings** → **Developer settings** →
**Personal access tokens** → **Fine-grained tokens** → 点开你这个令牌 →
**Repository permissions** → 把要的权限改成 `Read and write` → **Save**。
改完把新令牌重新填进 `.env` 的 `GITHUB_TOKEN=`(权限变更后令牌字符串不变的话不用改)。

**补了 `Issues: Write` 之后**,可以让我给那 5 条 Issue 打上 `priority:P0` / `priority:P1` /
`area:*` 标签 —— 否则工作台的**优先级分组在真实数据上一直是空的**(快照数据不受影响)。

## 第 4 步(可选):启用角色令牌认证

现在是**演示模式**:角色由前端下拉选择,`/api/auth/mode` 如实报 `enforced: false`,
界面也显示黄色提示「不构成认证」。想真正启用认证:

1. 生成三个随机字符串当令牌(例如 `openssl rand -hex 16` 跑三次)
2. 编辑 `.env`:
   ```ini
   DEVFLOW_ROLE_TOKENS=viewer:你的viewer令牌,member:你的member令牌,maintainer:你的maintainer令牌
   ```
3. 重启后端:
   ```powershell
   docker compose up -d --force-recreate backend
   ```
4. 之后请求必须带 `Authorization: Bearer <令牌>`(或 `X-DevFlow-Role-Token: <令牌>`),
   缺失或不匹配一律 **401**

**注意**:工作台的演示界面**不会**自动带令牌。开启后前端下拉会失效(请求 401),
需要你自己用 curl / Postman 调,或者改前端代码带上令牌。

## 附录:本机环境的两个必须知道的坑

### 1. Docker Desktop 必须从开始菜单启动

如果它是由脚本/终端拉起的,**那个会话结束时可能被连带终止** —— 现象是容器本来跑得好好的,
过一会儿 `docker info` 突然连不上,`wsl -l -v` 显示 `docker-desktop` 变成 `Stopped`。
这个会话里被杀了三次。从开始菜单手动启动则不会。

### 2. GitHub 加速器(Steam++ / Watt Toolkit)会让容器连不上 GitHub

它把 github 域名写进宿主机 hosts 指向 `127.0.0.1`,但**容器里的 127.0.0.1 是容器自己**,
于是 `httpx.ConnectError`;它还做 TLS 中间人,容器默认 CA 也校验不过。

已经准备好一键方案:

```powershell
pwsh -File scripts/enable-github-accelerator.ps1
```

它会导出加速器根证书 + 用 `docker-compose.accelerator.yml` 重建 backend。
**只有在 `DATA_SOURCE=github` 时才需要**,snapshot 模式完全用不到。

> ⚠️ 这等于让容器信任一个本地中间人根证书。默认不开启,`backend/certs/extra-ca/` 为空时行为与默认一致。
