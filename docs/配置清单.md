## ✅ 那个偶发引用问题已修掉(2026-10-06)

原先 `no-evidence-question` 约 1~2 成概率失败:答案是「未找到」,下面却列着引用。

**排查结论**:提高覆盖率阈值 / 把缺失词项计入分母 / IDF 稀有度,**三条路都走不通** ——
离题查询的覆盖率反而高达 1.00(分母剔除了缺失词项,命中所有*存在*的词就是满分)。

**真正的分界不是相关度,而是「查询里真正在语料中出现过的词项个数」**:
正常查询 3~6 个,这类离题查询只有 2 个 —— 这个数改写不了。

**修法**:两道门槛。「把候选给模型看」和「把引用标给用户」本来就不是一回事:

- 检索门槛(不变):宽松,保证模型不缺上下文
- **引用门槛(新增)**:存在词项 ≥3 才作为「依据」呈现

实测 `量子 系统 设计`:**命中 2 条(模型仍看得到)但可引用 0 条**。
弱命中的 summary 会追加「相关度不足,仅供参考,不作为依据」——
把不确定性说给模型听,而不是替它下结论。

## 启用角色令牌认证(生产协作测试用)

### 为什么要开

默认是**演示模式**:角色由请求头 `X-DevFlow-Role` 自称,服务端照单全收。
**那不构成认证** —— 任何人传 `maintainer` 就能执行写操作。
`/api/auth/mode` 会如实报告 `enforced: false`,前端也会显示黄色提示。

### 怎么配

**1. 生成令牌**(随便什么随机串都行,下面用 GUID 派生):

```powershell
function New-Token([string]$prefix) {
  "$prefix$([guid]::NewGuid().ToString('N').Substring(0,20))$([guid]::NewGuid().ToString('N').Substring(0,12))"
}
New-Token 'dv_viewer_'; New-Token 'dv_member_'; New-Token 'dv_maint_'
```

**2. 写进 `.env`**(格式 `角色:令牌`,逗号分隔):

```ini
DEVFLOW_ROLE_TOKENS=viewer:dv_viewer_xxx,member:dv_member_yyy,maintainer:dv_maint_zzz
```

角色只有三个:`viewer`(无写权限)、`member`、`maintainer`(后两个都有写权限)。
格式错的条目会被**忽略并记警告** —— 不让一个手误把权限体系降级成"谁都能过"。

**3. 重启后端**,然后用 `/api/auth/mode` 确认:

```powershell
curl http://localhost:8000/api/auth/mode
# {"enforced": true, "mode": "token", "roles": ["viewer","member","maintainer"], ...}
```

**4. 页面上填令牌**:`enforced: true` 时,顶部角色选择器旁会出现一个密码框,
把令牌粘进去(存 `localStorage`,刷新不用重填)。

### 带上令牌的两种方式

```
X-DevFlow-Role-Token: <token>
Authorization: Bearer <token>
```

### 保护范围(默认拒绝)

**令牌模式下,所有 `/api/*` 都要求有效令牌**,只放行三个:

| 路径 | 为什么放行 |
|---|---|
| `/api/health` | 负载均衡/容器探活,不能要求凭据 |
| `/api/auth/mode` | 前端要靠它知道要不要显示令牌输入框 |
| `OPTIONS` 预检 | 预检本身不带凭据,拦掉浏览器会以为整个跨域不可用 |

> **这条边界曾经是错的**:令牌校验原先只挂在**写接口**上,读接口(仓库列表、审计日志)
> **完全敞开** —— 无效令牌甚至不带令牌都能读到数据。逐个接口挂依赖是
> 「默认放行、显式保护」,漏一个就是一个洞。现在改成中间件层的
> 「默认保护、显式放行」,方向反过来才是安全的默认值。
