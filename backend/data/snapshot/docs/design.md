# 系统设计说明

## 认证与会话

认证层拆成两块:`auth/login` 负责凭据校验,`auth/session` 负责会话生命周期(签发、续期、失效)。

会话存储通过接口抽象,当前有内存实现与 Redis 实现两套。**切换实现不允许改动调用方**。

## 数据流

1. 客户端提交凭据
2. login 层校验凭据,失败直接返回 401
3. 校验通过后交给 session 层签发 token
4. session 层写入会话存储,并返回 refresh_token

## 为什么 token 过期要清理旧 session

旧实现里 token 过期后仍复用原 session 对象,导致 refresh 分支读到的是已失效的会话,
表现为「刷新令牌后依然 401」。v1.2 改为过期即清理、签发新会话。

## 测试策略

登录链路必须有集成测试覆盖三条路径:密码错误、token 过期、正常登录。
纯单元测试覆盖不到 session 存储与 login 层的交互,这次的回归就是这样漏掉的。
